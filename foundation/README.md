## ローカルでの作り方

Node.js 22 以上。実行はリポジトリのルートから。

```sh
node scripts/build-brawl.cjs --write
node scripts/build-brawl.cjs --check
node tests/foundation-build-smoke.cjs
node tests/foundation-2v2-gameplay.cjs
```

- `--write`: **新しい foundation 内の2つの生成HTMLだけ**を更新。旧試遊HTML、既存のFirebaseコード、Google Sitesは変更しない。
- `--check`: 現在の共通ファイル＋元ページからビルドした2ファイルと、GitHubにチェックインされている2ファイルが**バイト単位で一致すること**を確認。一方だけ再生成することを認めない。
- コア設定を変える場合は契約ファイルを変更してから両ビルドを生成し、CIを通す。生成HTMLを直接手でいじらない。
- 全バージョンは単一HTMLのまま動作し、外部JavaScriptの追加ダウンロードを必要としない。学校iPadやGoogle SitesのCSPに備えた方式。

## V1.1 — 実際の武器ルールも共通化（2026-10-12）

- [共有武器ルール](../shared/runtime/weapon-rules.inc.js) をビルド時に**1vs1と2vs2の両方の実行HTMLに埋め込む**。タンク散弾角、ガンナー3連射の角度と105ms／強化57msの間隔、強化リロード750ms、スナイパーGADの吹き飛ばし120、弾速660を共通定義から生成する。
- **1vs1実ゲーム側も変更:** タンクの散弾最大±0.23→±0.20、ガンナーは3発すべて最初の位置から放ち扇状の角度を付ける、弾の発生地点をキャラの中心から前方28へ、強化リロードを約694ms→750ms、スナイパーGADのBOTへの吹き飛ばしを160→120に変更。以前の1vs1試遊版は変更せず比較可能。
- **2vs2実ゲーム側も共通APIに移行:** ホストが処理する弾幕の生成間隔、銃弾の移動速度、強化リロード、BOT判断、GADノックバックで共通APIを使用。元と同じ数値を保持。
- [実弾生成のクロスモード比較](../tests/foundation-weapon-parity.cjs) を新設。1vs1の実際の `fireVolley` と2vs2の `BrawlCombatV8.accept` を比較し、角度、時間差、銃口基準、弾数をチェック。従来の両モードのブラウザ試遊テストも継続。
- これで**共通化済みの範囲は武器基礎と一部の計算**まで広がったが、HPの適用・射撃全体の管理・ガジェット全種類・オンライン同期・UI描画のエンジン一本化はまだ未了。これらを達成したと表現しない。

## V1.4 — ガジェットとウルトの共通エンジン（2026-10-12）

- **[abilities.inc.js](../shared/runtime/abilities.inc.js)**：ガンナー（弾薬全回復＋3秒強化）、ボマー（弾薬1補充＋強化弾準備）、スナイパー（140距離以内に衝撃＋ノックバック）のガジェットを**両V8の実際のaccept処理から共通呼び出し**。射撃の弾生成・HP確定とは別の発動責務をここに集約。
- **4キャラのウルト**（タンクの着地予約、ガンナーの5秒強化、スナイパーのレーザー予約、ボマーの3連爆弾予約）も同じソースで処理。使用条件・ウルト量不足・着地不可の場合の拒否は旧V8の状態遷移を維持。
- **タンクGADはあえて別仕様**：1vs1は単独ダッシュ、2vs2は味方とのガーディアンリンク付きダッシュ。移動距離115・2vs2リンク3.2秒の数値は同じ[共通契約](../shared/brawl-core-contract.json)から設定するが、誰を守るかの選択は2vs2モードに残す。
- [abilities-parityテスト](../tests/foundation-abilities-parity.cjs) を追加。両方の**実V8 accept**で各GAD/ULTの正常発動、弾薬・ウルト消費、不足での拒否、古いlife、二重イベント、味方リンクの違いを検証。共有コードが両出力で一致することも確認。
- バランス数値自体は変更せず、1vs1/2vs2の発動処理の二重実装を削減。元の単独HTML試遊版とFirebase運用版は変更していない。
- **残り:** 1vs1旧ソロ/オンラインのV8外に残る技演出・発動、2vs2固有Guardian Link、BOTの戦術・UI・オンライン通信はまだモード固有。上記の共通化がすべての技演出や本番オンライン挙動を統一したことにはならない。

## V1.3 — HP・試合状態・回復計算の共通化（2026-10-12）

- [共通試合状態コード](../shared/runtime/match-state.inc.js) `BrawlMatchV1` を追加し、1vs1と2vs2両方のV8ホスト戦闘コアが、ヒット時のHP減少・ウルトチャージ・被弾時のステルス解除・ボマーのDOT/鈍足、KOのラウンド/マッチ決着、AREA占領・妨害・時間切れ判定を同じコードから処理するようになった。
- 2vs2のタンク専用リンク対象の判断はモード固有に残し、リンク時の35%軽減・防いだダメージの蓄積は共通コード内で処理。1vs1に味方が存在しないのにリンクを追加する変更はしない。
- **1vs1のBOTとオンライン候補の自然回復、および2vs2のV8自然回復**が共通の回復計算式を使用。ただし条件判定と時間間隔は従来どおり、1vs1ローカルは最大400ms分・小数を丸めない、1vs1オンライン候補は最大500ms分・小数1桁、2vs2はcombat tick・小数2桁で維持。
- [HP/KO/AREA クロスモードテスト](../tests/foundation-match-state-parity.cjs) を追加。通常・オーバーキル・シールド軽減・DOT・KO連勝・同時KO・AREA競合/時間切れ・復活保護・自然回復の境界を検査。
- [共通ビルドと両モードのブラウザ回帰](../.github/workflows/foundation-build.yml) にテストを追加し、生成HTMLが共通コードへ接続されていることも検証。
- **まだ統合していない部分:** V8の全初期化・入力受付・ホスト権限・個別技、1vs1の旧オンライン/単独BOTの全HP状態管理、2vs2の戦術BOT、マップ描画/操作UI、Firebase通信プロトコル・実機iPadでの同期確認。共通のHP計算関数を使っていても通信の権威管理を統合したわけではない。
- 既存の比較用1vs1/2vs2、旧オンライン版、Firebase Rulesには変更を加えていない。変更は新しい生成候補とそのソース・テストのみ。

## V1.2 — 命中判定・弾薬補充・V8弾生成も共通化（2026-10-12）

- [projectile-physics.inc.js](../shared/runtime/projectile-physics.inc.js) を作成し、**1vs1の従来の試合中の `moveBullet`、1vs1と2vs2のV8ホスト戦闘更新、2vs2の描画用 `projectileStep`** に同一の分割移動／壁・範囲・敵キャラ命中判定／ダメージ計算を適用。
- タンクの減衰ダメージ、スナイパーの距離威力、ULT弾の別威力などの判定を同じ場所で管理。円形の当たり判定境界では距離が半径と一致した場合も命中扱いに統一。
- [combat-actions.inc.js](../shared/runtime/combat-actions.inc.js) に、両V8エンジンで元から同一だった `ammo` と `burst` 関数を移動。**実際に両ゲームで1つのソースが実行される**。全初期化処理・ヒット後のHP処理は依然モード別。
- [投射物クロスモードテスト](../tests/foundation-projectile-parity.cjs) で弾の壁すり抜け・射程限界・威力計算・両ホストエンジンで同じ敵HPが減ることを検査。[共通弾薬・弾生成テスト](../tests/foundation-combat-actions-parity.cjs) で弾数補充・強化リロード・タンク5発・ガンナー3発を検査。
- ビルダーには `initialize`/`ammo`/`burst` が必ず1個ずつ生成される安全検査を追加。共有関数の展開時に初期化を欠落させる回帰を防止。
- 以前の試遊版・本番オンラインのコードを変更していない。オフラインの新生成版のみで検証。
- 未完了: **モード間のホスト権限・入力同期・ガジェット/ウルトの全処理・BOT戦術・通信権限・表示エンジン**。V8のヒットHP確定・試合決着判定はV1.3で共有済み。ここまでを「全エンジン一本化」と呼ばない。生成版の1vs1操作と2vs2の4画面ブラウザ試遊は継続テストする。

## 何が自動で統一されるか

現在は、**キャラの基本値**（HP・移動速度・通常攻撃の基本ダメージ・射程・リロード）、コンバットコアに渡す**共通バランスパラメータ**、**同じタンクの減衰計算・ウルトジャンプ時間計算**、**霧の索敵ルール**が両モードの実際の出力に埋め込まれる。

テストでは共有ファイル中の移動速度やタンクの威力を変更したコピーを使い、両方の生成物が一緒に変わることを確認する。ブラウザテストでは1vs1のBOT開始・GAD消費、2vs2のBOT開始・GAD/ULT準備・HUD/ボタンの重なりを検査。

## 敢えて変更しない仕様

- 人数（1vs1/2vs2）、マップ（1000x600/1536x860）、カメラ、ガスの最大縮小範囲、2vs2のAREAモード、ルームnamespace/プロトコル。
- 1vs1の味方不在タンクと2vs2の味方リンクはそのまま。勝手にガジェット変更しない。
- 以前の1vs1/2vs2候補はリリース比較用に保存。どれが次の本番候補になるかもユーザー試遊で決める。

## まだ共通化していない部分（重要）

**戦闘エンジン全部や描画UIの一本化は未完了。** 独立した `src/modes/` テンプレートに残る通信・BOT・旧1vs1の技処理・モード固有UI処理は各モードで保守する。一方、共有できる弾薬補充・弾生成・投射物の分割移動/命中/ダメージは共通ソース化済み。

既知の残差は発射ループ全体の権限・同期差、ガジェット固有の違い（特に味方がいるタンクのガード）、1vs1のBOT行動、UI/カメラ、オンライン同期。タンク散弾角とガンナー連射座標などはV1.1で統一した。これらを現状一致していると扱ってはいけない。

次に設計するときは、1vs1/2vs2の違いをモード層へ隔離し、残る旧オンラインHP状態・入力権限・旧UI側の技処理・BOT・UIの共通化可否を、安全性と回帰テストを前提に検討する。**先に比較テスト・既存動画やスクリーンショット・オンライン安全要件を準備してから**移行する。

## 品質上の制約

Chromium自動テストに合格しても、学校iPad Safariの実機、Google Sites、Firebase 4人同期、通信負荷、長時間対戦は未検証。BOT候補をオンライン版完成とは呼ばない。

[ユーザー提示前のUI品質基準](../BRAWL_UI_PRE_RELEASE_GATE.md)を引き続き遵守し、UIが邪魔な状態で試遊を渡さない。
