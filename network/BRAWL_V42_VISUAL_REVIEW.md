# BRAWL V4.2｜画面を見て評価するレビュー

対象：**生成された開発版**の通常・ドラフト2vs2。撮影 2026-10-20、WebKit 1024×650タッチモード、ローカルFirebase Emulatorで4端末に接続。Google Sites・実Firebaseにはアクセスしていない。

## 今回の実映像

CI artifact **brawl-v42-2vs2-local-video-review** に以下の短い録画を保存（7日保持）。録画は試合中だけでなく、参加・待機操作も含む。

- v42-normal-2v2-host.webm（約7.5秒）
- v42-normal-2v2-guest.webm（約6.8秒）
- v42-draft-2v2-host.webm（約9.2秒）
- v42-draft-2v2-guest.webm（約9.8秒）

**目視の暫定所見**

1. フィールドの壁・ブッシュ・キャラ・色分けは視認できる。キャラの砲身の向きや体力バーは見える。
2. 画面幅1024px程度では、左上の弾数・ULT・味方残HP、中央上のスコア、右上の敵HP・ミニマップの文字が非常に小さい。射撃・回避・敵位置を同時に追っていると読みづらくなる懸念。
3. ミニマップとHUDがワールド上に重なるため、特に画面右上の障害物や敵周辺が隠れないか検討が必要。右下にはJUMP/GAD/ULT等の操作が集まり、タッチで誤操作しないか実戦プレイで確認したい。
4. 撮影された発射イベント・ラウンド終了は画面上で追えるが、場面は短く、味方・敵が大きく動く継続戦闘を再現していない。**弾が遅れない、画面がカクつかない、快適であるとの結論は出せない。**
5. 通信遅延の実測ではない。WebKitはSafariに近い描画エンジンだが、学校iPad実機やGoogle Sitesの埋め込み、校内Wi-Fiとは条件が異なる。

## 今後のレビュー基準（CIの成功・FPS値と別の軸で判定）

- 動画：移動+射撃+壁+弾が同時に登場する**20〜30秒以上の実戦風シナリオ**をホストとゲスト双方で撮影。動画記録のフレーム落ちとゲーム内フレーム落ちは混同しない。
- 弾：発射ボタンの直後に自分の弾が自然に出るか。他人の弾が突然現れたり消えたり、速さが急変・逆走したりしないか。ボマーの放物線・着弾表示も対象。
- 動き：敵の位置が飛ばないか。カメラ・キャラ・照準の進行が連続しているか。
- UI：キャラが重なった時の識別、敵/味方HPと弾数、ミニマップの遮蔽、右下タッチ操作の押し分け、ラウンド切替の明瞭さ。
- 観察の限界：通常のCI数値テストと録画視察は両方必要。映像内の動作が正常でも、学校Wi-Fiの体感品質は別途検証。

**次の改善**：診断パネルを隠したまま複数端末が動き、ボマー・スナイパーなど異なる弾を連続使用するシナリオに拡張する。UIレイアウト変更は個別のビフォー/アフター比較と君の確認を踏まえて決める。
