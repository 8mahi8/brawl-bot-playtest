# BRAWL 友達対戦 V2｜学校iPad向け試遊手順（開発版）

2026-10-13。ユーザーから学校のiPadでの試遊許可あり。まずオンラインが遊べるか確認する目的であり、公開後も改善する。Google Sitesの既存掲載内容は自動では書き換えない。

## 使うHTML

- 1vs1：`online/ipad-duel-v2-lab.html`
- 2vs2：`online/ipad-squad-v2-lab.html`

HTMLはどちらもスタンドアロン。GitHubの該当ファイルを開いて **Raw（生ファイル）をコピー**し、Google Sitesの「挿入」→「埋め込む」→「埋め込みコード」に**全文**を貼る。ファイルへのGitHubリンクだけを埋め込むのとは異なる。試験する際は現在使用中のページを消さず、別の試遊ページに追加する。

**このプロトタイプには本番FirebaseのURL・鍵を入れていない。** オンライン対戦時には一度、画面の「通信接続設定」に、以前からユーザーが利用している**本人管理の Firebase Realtime Database URL**を入力する。部屋作成と参加側で同じURLを使う。クラウドDB側のRulesが新しい `brawl_v2_duel_rooms` / `brawl_v2_squad_rooms` の読み書きを許していないと接続できない。元のFirebaseルールを安易に全開放しない。エミュレーター用のOPEN rulesを本番にコピーしない。

## 一人＋スマホの1vs1試験

1. PC側の1vs1試遊ページから通信接続設定を入力し「ルームを作成」。5桁のルームIDを控える。
2. スマホ側で同じ1vs1試遊ページを開き、同じFirebase URLを指定。「ルームに参加」から5桁IDを入力し「BOT端末として入室」を選ぶ。
3. PC側でキャラを選択してREADY。スマホはBOT役になり、試合の開始を待つ。両方のブラウザを開いたままにする。
4. PCの移動がスマホ側でも変わるか、射撃とHP、KO、再戦まで確認。音声は不要。

2人の手動操作で試す際はスマホでも「ルームに入る」を選び、それぞれREADYを押す。

## 2vs2の試験

4つの別ブラウザ/端末で同じ試遊ページに入る。ホストが「4人ルームを作る」、他の3人が同じ5桁IDで入室し、全員READY。KOとAREAの両方で移動・射撃・HP・勝敗・再戦を確認。BOT端末も1席として入れるが、4つの席すべてを埋める必要がある。

## 既知の制約

- 以前のBRAWL HTMLにURLがあっても、**新しいルーム領域がFirebaseルールで許可されるかは別**。接続エラーの場合は接続設定とRTDB Rulesを確認する。
- Github Actionsの公式Firebase RTDBエミュレーター/複数WebKitテストはクラウド本番回線の速度を証明しない。iPadの操作遅延とWi-Fi実測は別途必要。
- 実際のGoogle Sites iframeでは画面のクリップや通信SDK読み込みに制約がありうる。先にGoogle Sitesの新規試用ページで確認し、既存版は保持。
- 5桁IDは認証用パスワードではない。データベース側を無制限公開しないこと。
